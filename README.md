# ХОККЕР — фронтенд (шаг 1: каркас + вход по SMS)

React + Vite + Tailwind, PWA. Пока реализовано: вход/регистрация по SMS-коду,
базовая оболочка приложения (нижняя навигация по ролям), экран профиля
с привязкой Telegram. Остальные экраны — заглушки, появятся на следующих шагах.

## Локальный запуск

```bash
npm install
cp .env.example .env
# отредактируйте .env — впишите адрес вашего бэкенда (Timeweb App Platform)
npm run dev
```

Откроется на http://localhost:5173

**Важно:** на бэкенде должен быть настроен CORS для этого адреса.
В `.env` бэкенда (`CORS_ORIGINS`) должно быть перечислено `http://localhost:5173`
через запятую вместе с остальными разрешёнными адресами.

## Деплой на Timeweb Cloud App Platform

Тип деплоя — **Dockerfile** (как и у бэкенда). Особенность: адрес API
(`API_BASE_URL`) подставляется **при старте контейнера**, а не при сборке —
это позволяет один и тот же собранный образ использовать с разными бэкендами
без пересборки.

1. App Platform → Создать приложение → тип **Dockerfile** → подключите
   репозиторий `hokker-frontend`, ветка `main`.
2. Переменные окружения (`ENV`):
   - `API_BASE_URL` — полный адрес вашего задеплоенного бэкенда, например
     `https://emilmurtazin-hokker-e65f.twc1.net` (без слэша в конце)
3. **Обновите `CORS_ORIGINS` на бэкенде**, добавив туда домен, который
   Timeweb выдаст этому фронтенд-приложению после деплоя — иначе браузер
   заблокирует все запросы к API (см. раздел про CORS ниже).
4. Запустите деплой, откройте выданный домен.

## Почему это важно: CORS

Браузер — не curl. Он блокирует запросы с одного домена (фронтенд) к
другому (бэкенд), если сервер явно не разрешил это через заголовки CORS.
Мы это настроили на бэкенде (`CORS_ORIGINS` в его `.env`), но при каждом
новом домене фронтенда (например, если Timeweb сменит поддомен, или вы
подключите свой домен) нужно **добавлять его в CORS_ORIGINS на бэкенде**
и передеплоивать бэкенд — иначе фронтенд будет виден в браузере, но все
запросы к API будут падать с ошибкой CORS в консоли разработчика.

## Структура проекта

```
hokker-frontend/
├── Dockerfile           # сборка + раздача через nginx
├── nginx.conf            # SPA fallback (client-side роутинг)
├── entrypoint.sh          # подставляет API_BASE_URL при старте контейнера
├── public/
│   └── config.js           # рантайм-конфиг (сюда подставляется адрес API)
└── src/
    ├── api/client.js         # обёртка над fetch, авто-refresh токена
    ├── context/AuthContext.jsx  # состояние авторизации
    ├── components/BottomNav.jsx # нижняя навигация (зависит от роли)
    └── pages/
        ├── AuthFlow.jsx         # вход: телефон → код → регистрация
        ├── Profile.jsx           # профиль, привязка Telegram, выход
        └── ComingSoon.jsx         # заглушка для будущих экранов
```
